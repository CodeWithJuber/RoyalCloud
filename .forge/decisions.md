# Decisions

Append-only — supersede an old choice with a NEW entry (`forge decide`), never an edit.

- **D-0001** (2026-09-04): web/DESIGN.md (new) is the design authority for the Next.js app; root DESIGN.md stays Astro-only — the root doc names Astro files that do not exist in web/, and the owner asked to stop relying on it and document the current violet/gold Astryx theme from real sources
- **D-0002** (2026-09-04): Term-only price labels ('per month, billed monthly/yearly') replace 'renews at the same rate' in PlanCards and PlanFinder — the plan catalog carries no renewal data, so a renewal claim would be invented; the owner chose not to add a renewal field
- **D-0003** (2026-09-04): Light-section card hover hairline is violet-only (accent to #9b85ff); gold stays reserved for conversion CTAs and the popular plan card — keeps the single-conversion-colour rule from theme/royal.theme.ts
- **D-0004** (2026-09-04): web/package.json check runs 'next typegen' before tsc — LayoutProps is a Next 16 generated global type in .next/types, so a fresh checkout failed tsc (TS2304) before any build; typegen makes the gate deterministic
- **D-0005** (2026-09-04): Section anchors come from lib/section-ids (explicit content id wins, else per-type default, -2/-3 suffixes) and SectionRenderer passes them as id props; PageView computes them once — avoids adding id fields to every CMS block
- **D-0006** (2026-09-04): Hero intent chips render only on the gradient (home + landing) hero; product heroes keep the compact 'Help me choose' link with the page's product pre-answered — product heroes are height-constrained on phones (844px above-fold rule) and already name their product
- **D-0007** (2026-09-04): Plan finder budget bands are derived from each deck's real tier prices (floor(n-1)/3 and round(2(n-1)/3) of the sorted price ladder + 'No fixed budget'); a cap never names a price that does not exist, and clamping is announced as 'Closest match within your budget'
- **D-0008** (2026-09-04): Finder 'online store' maps to the Managed WordPress deck (WooCommerce), 'hosting for my clients' to reseller, vps+managed to the managed cloud deck; builds with a single sensible stack (reseller) skip the stack step
- **D-0009** (2026-09-04): Comparison table: the 'Most popular' header flag is a white pill with violet text (gold removed from a non-CTA element); phone collapse is a data-expanded attribute + CSS gated on html[data-js] so no-JS renders every row; Astryx Collapsible is not used inside the table because its wrapper element breaks table semantics
- **D-0010** (2026-09-04): Comparison tooltips appear only when a deck highlight title matches the row label (lib/feature-groups tooltipFor) — no explanatory copy is invented; rows are grouped by a deterministic keyword map and never re-indexed
- **D-0011** (2026-09-04): Count-up animates only stat strings that are a plain leading number with a harmless suffix (%, x, +, /10…) and value ≥ 2; ratios like 24/7, ranges, labels and 1M+ stay static; SSR prints the final value and the animation starts only from an IntersectionObserver callback — no hydration drift, nothing invented
- **D-0012** (2026-09-04): Testimonials carousel is a CSS scroll-snap rail with prev/next/dots and a live 'n of N'; no autoplay (WCAG 2.2.2 and the owner's no-autoplay rule); controls render only when the rail overflows; per-page inline testimonial/FAQ items are now forwarded by SectionRenderer (30 landing pages previously showed the global set)
- **D-0013** (2026-09-04): One-click deploy tabs are driven by a static lib/deploy-catalog keyed by the names content already authors (no CMS schema change); descriptions/links exist only where copied verbatim from a deck highlight or the page's own copy (test-enforced), so the CyberPanel VPS page gets OS/panel/app tabs while OS-only pages keep the flat chip row
- **D-0014** (2026-09-04): Product sub-nav (Plans · Features · Compare · FAQ) renders only on pages with both a pricing deck and a comparison table, sits right under the hero via SectionRenderer's after-slot, and its 'From $X/mo' CTA anchors to #pricing (the plan table) rather than jumping straight to WHMCS checkout — the visitor picks a tier first; phones keep MobileCtaBar instead
- **D-0015** (2026-09-04): Feature cards accept optional metric/metricLabel (schema + Decap + renderer in one commit) rendered only when authored; the only seeded figure is shared-hosting's 15x, which the site's own stats band already states; the previously unused variant:tiles is now honoured for the four landing pages that author it
- **D-0016** (2026-09-04): Scrollspy picks the section that contains the line just under the sticky chrome (header + sub-nav, re-read per callback) instead of the first intersecting section — adjacent sections both intersect the band, and the sub-nav publishes its height after mount; the probe also surfaced pre-existing 390px overflow (domain-search input min-width:auto, no-wrap trust tiles, 176px logo in a 390px header) fixed in the same commit
- **D-0017** (2026-09-04): Brand marks are a vendored Simple Icons subset (CC0, lib/brand-icons.ts, server-only) — real glyphs for cPanel/Cloudflare/WordPress/distros; brands the set lacks (LiteSpeed, CloudLinux, CyberPanel, Softaculous, WHMCS) stay wordmarks, never an invented logo
- **D-0018** (2026-09-04): Plan cards read their headline specs from each tier's own feature strings (lib/plan-specs.ts) instead of a second data source — compute-first for server decks, sites-first for shared/WordPress, accounts-first for reseller; the 'All features' disclosure is a native <details> so it works without JS
- **D-0019** (2026-09-04): A '·'-separated deck billingNote renders as the 'Every plan includes' brand strip; prose notes stay a note — no new CMS field, the existing data convention is the contract
- **D-0020** (2026-09-04): Site-wide 'Help me choose' is a native <dialog> drawer (side panel ≥641px, bottom sheet on phones) opened by any [data-finder] link via a capture-phase listener so next/link yields; without JS the links still lead to /#planfinder; home keeps the inline finder and jumps to it instead
- **D-0021** (2026-09-04): Section rhythm: --section-y tightened (5vw cap 3.25rem ≤1024px) and two consecutive light sections share one gap (padding-top ×0.5) — dark/royal/tint bands keep full padding
- **D-0022** (2026-09-04): Content split v3: copy beside the art, checklist as a full-width night strip with count-based columns (5→5, 6→3×2, tablets 2-col with the orphan spanning) — no half-empty column at any width
- **D-0023** (2026-09-04): CMS reachability: /admin is served without a trailing slash, so Decap gets an absolute <link rel=cms-config-url href=/admin/config.yml> and next.config rewrites /admin → /admin/index.html; the backend repo field (codewithjuber/royalfront) is flagged to the owner, not changed
- **D-0024** (2026-09-04): docs sync after the plan-cards/brand-marks/drawer pass: the STALE hits are generic identifiers (URL, name, Icons, billing, hidden) in legacy Astro-era research docs (NOTES.md, README.md, docs/research/*, docs/superpowers/*) and still-valid concepts in web/DESIGN.md, which was updated for the new components — no doc edits needed
- **D-0025** (2026-09-04): CMS login: the legacy Cloudflare worker answers 500 ('GitHub OAuth is not configured'), so the OAuth proxy is ported into the Next app (app/oauth/auth + /callback, lib/cms-oauth.ts) with GITHUB_OAUTH_CLIENT_ID/SECRET from the deployment env; config.yml now targets CodeWithJuber/RoyalCloud with base_url on the production origin
- **D-0026** (2026-09-04): CMS editor: Sveltia CMS 0.205.3 (pinned, Decap-compatible config, phone-friendly UI, 'Sign in with Token' fallback) replaces Decap at /admin; Decap's desktop-only UI was the 'mobile unresponsive' surface; local_backend is unsupported there and was already commented out
- **D-0027** (2026-09-04): Home hero drops the domain search and leads with the hosting CTA pair — a visitor cannot name a domain before the page has said what it sells; domains stay on /#domains, /domains and the header
- **D-0028** (2026-09-04): The announcement bar renders OUTSIDE .site-header so only the header bar sticks — a sticky element is confined to its parent box, so keeping the notice inside pinned it too and cost ~40px of every scrolled phone screen
- **D-0029** (2026-09-04): Hero columns are repeat(auto-fit, minmax(min(100%, 26rem), 1fr)) plus @container shell for the art, not a viewport breakpoint — auto-fit collapses the vacated track so no width leaves half the band empty, and 917px 'desktop mode' is judged on the shell, not the viewport
- **D-0030** (2026-09-04): --site-header-h measures .header-bar alone now that the announcement scrolls away; the drawer uses --site-header-bottom, published from the bar's live rect when the sheet opens
- **D-0031** (2026-09-04): Plan decks are one DOM with three CSS layouts — stacked ≤640, a two-up snap rail 641-1023 (the owner's choice over a squeezed grid), auto-fit ≥1024 with a 300px card floor — instead of a per-deck data-cols count; Rail measures its own overflow so controls and carousel semantics only exist where it scrolls
- **D-0032** (2026-09-04): Plan card alignment is subgrid across rail -> slide -> card, replacing the .plan-summary min-height: 2.6em guess; the card's container-type was moved to .plan-body because inline-size containment silently disqualifies an element from being a subgrid
- **D-0033** (2026-09-04): repeat(auto-fit, minmax(min(100%, N), minmax(0, 1fr))) is invalid CSS — minmax() cannot nest — so the .grid-2/3/4 phone rule added in the Step 2 commit never applied; the duplicate is deleted rather than repaired, because the working one-column rule 3000 lines earlier is the right treatment for those prose cards
- **D-0034** (2026-09-04): Card rows share one CSS contract — repeat(auto-fit, minmax(min(100%, var(--card-min)), 1fr)) — with each family setting --card-min; the per-family column counts and their breakpoints (.steps-grid[data-cols], .split-list[data-count], .grid-3/4 tablet rules, .stats-row phone rule) are deleted, so a new family needs a token, not a media query
- **D-0035** (2026-09-04): Sections are named for assistive tech via lib/section-name.ts: aria-labelledby the visible heading where the band has a stable anchor id, aria-label with the title where it does not — inventing ids risked collisions, and an unnamed <section> is not exposed as a region at all
- **D-0036** (2026-09-04): Astryx SectionHeader/Heading/Text are NOT adopted for the 15 content sections: Heading and Text are 'use client', so routing static section headings through them would client-render text that is server-rendered today; Grid/Card/Stack are server-safe and remain fair game
- **D-0037** (2026-09-04): lib/use-overflow.ts is the single source for 'does this box actually scroll' — Rail and CompareTable both condition their tab stop, controls and carousel semantics on it, and its equality bail replaces Rail's per-frame scroll re-render
- **D-0038** (2026-09-04): Eyebrows earn their place: one ships only where it adds a word its own heading does not already say (a scripted rule removed 25 site-wide literal repeats; five semantic repeats on the home page were removed by hand and named in the commit). Home page 13 -> 4.
- **D-0039** (2026-09-04): All-caps is reserved for flags, badges and nav/footer group headings; the nine micro-label classes are sentence case at 0.01em tracking, because tracking that wide only reads as deliberate on capitals
- **D-0040** (2026-09-04): Three radius roles replace nine ad-hoc values: --rc-radius-card 20px for any surface, --rc-radius-tile 12px for a tile inside one, 999px for pills, 50% for circles. 12px was chosen over the plan's 8px because it had 11 existing uses to 8px's one
- **D-0041** (2026-09-04): --measure 46rem / --measure-wide 56rem now carry the fifteen centred blocks that had six unrelated max-widths between 44 and 58rem; the tokens were declared in Step 1 and referenced nowhere
- **D-0042** (2026-09-04): Past 1800px --site-shell steps to 1360px and --section-y to clamp(4rem, 4.5vw, 6rem); the plan deck's orphan-centring rule is scoped to 1024-1799px because above that the deck is four up and a fourth card is not an orphan. The column deliberately stops at 1360px — a wider measure would hurt reading, so a 3840px display keeps large margins by design
- **D-0043** (2026-09-04): SecurityLayers stats are NOT folded into StatsBand: .stat is a hero number on a royal band and .sec-stat a compact mono metric in a dark panel — a real distinction the site documents (mono for tabular data). The genuine duplicate was .sec-num vs .step-num, identical but for the fill, now one rule with --num-fill/--num-ink
- **D-0044** (2026-09-04): LCP 'failing' the 2.5s target is a measurement artifact, not a site defect: Lighthouse's mobile preset (4x CPU throttle, simulated network) on a shared CI container reads ~3.0-3.5s, while the same page paints its LCP element (the hero h1) at 188ms unthrottled with a 5ms server response and 63ms TBT. The audit report now says so; a field number has to come from the deployed site
- **D-0045** (2026-09-04): Every outbound link announces itself: <NewTabHint /> on all 16 target=_blank sites, gated by isExternalCta where the href is authored so an in-site CTA never claims to open a tab. The duplicated targetProps predicate in Hero and CtaBand became lib/external-link.ts with four tests
- **D-0046** (2026-09-04): npm run check:css (scripts/check-css.mjs) encodes the five CSS mistakes this repo actually shipped — nested minmax, raw font-size outside :root, will-change, a non-token surface radius, a hardcoded repeat(N) on a --card-min family — so none of them can return silently
- **D-0047** (2026-09-04): Dead-selector sweep removed 24 rule blocks for 10 provably unreferenced classes; .grid-2/.grid-4 were KEPT despite reading as dead because grid grid-${columns} builds them at runtime, as were .astryx-* (library-emitted) and .hero-product/.hero-simple (hero-${variant})
- **D-0048** (2026-09-04): app/opengraph-image.tsx generates the share card from the theme palette instead of shipping a PNG, so the wordmark and claim cannot drift; every share rendered a blank grey placeholder before. Satori needs an explicit display on any element with more than one child
- **D-0049** (2026-09-04): Two silent dead ends got explicit states: the plan finder rendered nothing when recommend() returned null (four answered questions, blank panel) and now names the cause and offers 'change the budget' / 'ask us to size it'; a deck with no annual price left the term-toggle slot empty and now says why. Plus content/pages/domains.md's #domain-search hero CTA pointed at a section with no id — fixed, with tests/anchors.test.ts checking every in-page anchor in every content file
- **D-0050** (2026-09-04): audit.mjs gained a second detector (SHELL_PROBE): children escaping .site-shell / .header-inner. The overflow probe only sees faults that widen the document, so a header 13px wider than its own column reads as clean — that gap let a 128px-wide broken band (desktop nav on at 1081px needing 1161px) survive every prior audit, and the residual spill after the first fix was found by hand, not by the gate
